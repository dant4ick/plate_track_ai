# Цвета приложения

`AppColors` хранит физические значения, `AppPalette` выбирает смысловые роли
для текущей темы, `AppTheme` задаёт пары цветов Material-компонентов.
Режим `system` выбирает Light или Dark по ОС; Pick me — отдельная светлая тема.

## Как выбирать роль

Primary во всех темах зелёный (`#B0DD4E`); secondary сохраняет цвет темы:
синий (`#4D55F5`) в Light/Dark и розовый (`#FF7AB5`) в Pick me. Акцент калорий
во всех темах — постоянный `#FF3372`, независимо от `colorScheme.primary`.
Графика и цветные подписи используют один цвет; подложки — нейтральный
`colorScheme.surface`, без полупрозрачных вариантов. Цвет знака логотипа (`#F9D9DA`) не является
фоном страницы; фон Pick me — `#FFF6F9`.

- Для компонентов Material берите фон и foreground парой:
  `primary/onPrimary`, `secondary/onSecondary`, `error/onError`.
  Основная кнопка добавления и все её варианты используют `primary/onPrimary`
  во всех темах, включая Pick me.
- Для статусов используйте `StatusSnackBar.success/error`. Они выбирают
  фон текущей темы и явный цвет текста/иконки. Светлые статусные константы
  вне темы напрямую не используются.
- Для подписи на сплошном цветном фоне используйте
  `palette.foregroundOn(background)`: он выбирает чёрный или белый по контрасту.
  На светлых лаймовых, розовых и статусных заливках нужен тёмный foreground.
- Для текста/иконок рекомендаций используйте `palette.accentInk`.
- Для ссылок, навигации, выбранных вкладок и активных Radio используйте
  читаемый foreground из темы, а не цвет заливки primary. TextButton, Radio,
  Switch и курсор ввода настроены централизованно в `AppTheme`.
- Switch сохраняет различимый thumb при нажатии, hover и фокусе; outline
  интерактивных контролов отделён от декоративного border.
- Содержательные подписи, значения, даты и оси используют `textSecondary`;
  прежний слишком бледный `textTertiary` удалён. Иерархия сохраняется размером
  и насыщенностью шрифта.
- Все столбцы калорий используют `#FF3372`. Обводка
  сохраняет различимость светлых заливок, а у выбранного периода она толще.
  Gauge также сохраняет `#FF3372` при превышении цели: состояние обозначается
  подписью «сверх», а не другим оттенком. График веса использует `colorScheme.primary` для линии, точек и заливки
  (12% для заливки), а `textSecondary`
  для линии цели без снижения прозрачности значимых линий и столбцов.
  Tooltip получает пару `inverseSurface/onInverseSurface`, независимо от
  цвета столбца и настроек библиотеки.
- BMR/TDEE используют нейтральную поверхность, границу `border` и текст
  `onSurface`: расчёт сам по себе не является предупреждением или успехом.
  Плашки завершения AI-анализа, успешного поиска штрихкода и общая
  мотивационная плашка рекомендаций удалены. Сообщение о ненайденном
  продукте — обычная подсказка; отсутствие пищевой ценности сохраняет
  предупреждение, потому что требует заполнить данные. Цвета калорий/БЖУ
  и обратная связь о сохранении/ошибке сохраняют свои смысловые роли.
- Для макронутриентов используйте `palette.styleOf(macro)`: `graphic` для
  диаграммы, `ink` для текста, `fill` для подложки. Белок `#FF7777`,
  углеводы `#FFCC77` и жир `#AF5BD0` используют один исходный цвет для графики,
  текста и иконок во всех темах: `ink == graphic`. Отдельных светлых/тёмных
  оттенков и полупрозрачных подложек БЖУ нет; `fill` — нейтральная
  `colorScheme.surface`. Исходные цвета, особенно углеводный на белом фоне,
  не гарантируют контраст текста 4,5:1 — оттенки ради контраста не подменяются.
  Подписи внутри секторов получают контрастный foreground
  самого сектора, а не Ink, предназначенный для поверхности карточки.
- Для поверхности карточки fallback — `colorScheme.surface`.
- Для полей явно заданы обычные, сфокусированные и ошибочные метки:
  текст использует `onSurface`, ошибка сохраняет красную границу.
  Маленькие подписи на field/placeholder/статусных заливках и подпись цели
  поверх области графика также используют `onSurface`; `textSecondary`
  остаётся для обычной поверхности карточки.
- Для нестандартной панели с явным `foregroundColor` используйте
  `StandardAppBar`: он задаёт также title/icon/action styles, которые иначе
  наследовались бы из обычной темы. Оба сканера используют эту панель.
- Для залитых кнопок с локальным фоном используйте `AppTheme.filledButtonStyle`.
  Он сохраняет контраст текста после наложения слоя feedback в состояниях
  hover/focus/press; единая прозрачность слоя — 8%. Локальные destructive
  кнопки и AppButton используют тот же метод.
- Для отдельных теней используйте `palette.shadow`, для составной тени
  карточки — `AppDimens.cardShadow(palette)`. Ambient и contact остаются
  разными слоями. Отдельные оттенки чёрного 10% и 12% удалены.

## Постоянные цвета и удалённые роли

Камера/сканер сохраняют белые элементы управления и чёрное затемнение поверх
живого изображения. Образцы в переключателе тем показывают палитру каждого
варианта независимо от выбранной темы. Маркер веса сохраняет лайм через
явную роль `weightAccent`; это тот же `secondShade`, новый оттенок не добавлен.

Удалены неиспользуемые `primeShade`, brandSoft/onBrandSoft, successSoft,
dangerBorder и цвета удалённой нижней навигации. Неиспользуемый getter `field`
удалён, но физические цвета полей сохранены в ThemeData.
Совпадающие значения разных смысловых ролей сохранены отдельными именами.

Объединены близкие пары через aliases:
`placeholderLight = fieldLight`,
`trackLight = borderLight`, `cameraMask = cameraPanel`. Раздельные имена
ролей сохранены для дальнейшей независимой настройки.
`warningSoftLight` сохранён как самостоятельный цвет статуса; оттенки БЖУ
`proteinInk/InkDark/Soft/SoftDark`, `carbsInk/InkDark/Soft/SoftDark` и
`fatInk/InkDark/Soft/SoftDark` удалены из физических констант.

Основная типографика Montserrat получает `bodyColor/displayColor` из активного
`colorScheme.onSurface`: полупрозрачный чёрный в Light/Pick me и белый в Dark.
Неявные базовые оттенки Material `#1D1B20/#E6E0E9` больше не используются
в качестве основного текста приложения.

Логотипы используют отдельные пары из экспорта Figma, без перекраски через
`primary/onPrimary`: Dark — `#4D55F5 / #DAFF7C`, Light — `#B0DD4E / #FFFFFF`,
Pick me — `#FF7AB5 / #F9D9DA`. Контуры, отступы и скругления сохранены в SVG.
Основная иконка приложения и Android launcher-ресурсы всегда синие с лаймовым
знаком и не переключаются вместе с темой. Исходник и генерация: [branding.md](branding.md).
Нативный фон запуска использует `?android:colorBackground` и следует теме ОС;
сохранённый в Dart выбор Pick me применяется после запуска Flutter.

## Проверка

Команды ниже выполняются внутри проектного Podman-контейнера, а не на хосте.
Вход в контейнер и настройка Flutter SDK в PATH описаны в [branding.md](branding.md#генерация).

```bash
flutter analyze
flutter test
PALETTE_PREVIEW=1 flutter test test/design/color_roles_preview_test.dart
```

Последняя команда сохраняет `build/previews/color-roles.png` с компонентами
в трёх темах. Это превью для визуальной проверки, а не платформозависимый
golden-тест. Контраст фон/foreground проверяется отдельно в тестах тем
и `StatusSnackBar`, включая текст/иконки, залитые кнопки и цвета макросекторов.
Отдельные регрессионные тесты проверяют состояния Switch/Radio, подписи и
tooltip графиков и реальные экраны BMR, рекомендаций и профиля во всех темах.
Также проверяются фактически разрешённые camera title/back/actions,
focused/error метки InputDecorator, контраст единиц веса на fillColor,
композиция слоя feedback кнопок и подпись цели поверх заливки графика.
